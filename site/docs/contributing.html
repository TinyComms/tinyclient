Contributing

From a typo to a network adapter. The full guide is CONTRIBUTING.md; this page is the short version.

Where help is needed

  • Real-account testing of Teams, Telegram and Signal, and of everything on Linux and Windows. A bug report with the redacted log is as useful as code.
  • Notifications and a dock badge, and the settings that control them.
  • An interactive terminal UI on the existing socket protocol. The protocol is all it needs.
  • Signal: attachments, safety numbers, calls.
  • Packaging: a notarized macOS build, Linux packages, a Windows installer.
  • Message search, video and screen share.

Start here

git clone https://github.com/itz4blitz/tinyclient
cd tinyclient
cargo test --workspace
TINYCLIENT_DIR=/tmp/tinyclient-demo cargo run -p chatd -- --seed-demo=live
TINYCLIENT_DIR=/tmp/tinyclient-demo cargo run -p tinyclient --features gui

Work against the demo or the tests’ local fakes. Run chatd with TINYCLIENT_DIR set while developing, so a half-finished change never touches your real sessions or cache. Build from source lists the prerequisites.

What a change must keep true

  • Budgets. A feature is done when it passes its memory, speed and idle budget, measured from outside the process.
  • Process boundaries. chatd never decodes media; mediad never runs without a call; the window never talks to a network.
  • Nothing automated, and nothing sent that the user did not ask for.
  • Protocol additions are optional fields, so an older frame still reads.
  • No new async runtime and no second TLS stack in chatd without a measured reason.
