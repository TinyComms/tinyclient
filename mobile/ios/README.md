# tinyclient for iOS — host skeleton

A three-file Swift shell around the Rust static library. Nothing here is a working app yet: the
pinned GPUI revision has no iOS backend, so the build stops at `gpui_platform` (see
`docs/mobile-build.md`). What this directory does is make the Xcode target, the plist and the
call into Rust reviewable *before* that migration, so it is a configuration change afterwards.

## Files

| File | Why |
|---|---|
| `project.yml` | XcodeGen definition. `.xcodeproj` is generated, never committed. |
| `Info.plist` | scene manifest, `UILaunchScreen`, version keys, `ITSAppUsesNonExemptEncryption` placeholder |
| `Sources/AppDelegate.swift` | `@main`, answers the scene configuration |
| `Sources/SceneDelegate.swift` | creates the window and calls the Rust entry point |
| `Sources/Tiny-Bridging-Header.h` | declares `tinyclient_ios_main()` |
| `TinyCore.xcframework` | generated by `scripts/mobile/build-ios.sh`, gitignored |

## Build (macOS only)

```bash
rustup target add aarch64-apple-ios aarch64-apple-ios-sim x86_64-apple-ios
scripts/mobile/build-ios.sh            # cargo → lipo → xcframework
cd mobile/ios
xcodegen generate
xcodebuild -project Tiny.xcodeproj -scheme Tiny \
  -destination 'generic/platform=iOS Simulator' \
  -configuration Debug CODE_SIGNING_ALLOWED=NO build
```

`xcodegen` comes from Homebrew (`brew install xcodegen`). `xcodebuild -create-xcframework`
refuses two slices with the same platform+variant, which is why the two simulator architectures
are `lipo`'d into one universal slice first.

## Deployment target and toolchain

* **iOS 17.0** floor. Xcode 27.2 supports 15–27; 17 is the pragmatic floor for a new 2026 app.
* Xcode 26.6 is fine today. From **April 2027** uploads need the iOS 27 SDK (Xcode 27), so the
  `macos-26` CI runner becomes `xcode-27` in Q1 2027.
* Swift 6 language mode, per Xcode 27 defaults. The shell has no concurrency yet, so there is
  nothing to annotate.

## Static linking

`TinyCore.xcframework` is a **static** library. The app target links `-lc++`, `-lz` and
`-lsqlite3` in `project.yml`, because a static library cannot bring its own system frameworks.
Bitcode is not used and must not be enabled (dead since Xcode 16).

## Before TestFlight (not done)

* `ITSAppUsesNonExemptEncryption` is `true` as a placeholder, with no
  `ITSEncryptionExportComplianceCode`. App Store Connect rejects the upload until the code from
  its questionnaire is in this plist.
* `PrivacyInfo.xcprivacy` is not present. Add it to Copy Bundle Resources when the core touches
  file timestamps, disk space or UserDefaults.
* Signing, `ExportOptions.plist`, fastlane `pilot` and an app icon are all absent.
