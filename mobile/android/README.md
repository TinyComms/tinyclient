# tinyclient for Android — host skeleton

This is the native shell around the Rust library. It contains no UI: `GpuiInputActivity`, a
NativeActivity subclass in `app/src/main/java/dev/gpui/mobile`, loads `libtinyclient.so` and the
Rust side draws everything. The subclass only carries the soft keyboard's text and the window
insets to gpui_ce_mobile, which NativeActivity cannot. See `docs/mobile-build.md` for the
full story and the verified/unverified split.

The launcher activity is `dev.tinyclient.app.TinyActivity`, a `GpuiInputActivity` that also
hands permission and screen-capture results to the call platform. The call platform and the web
sign-in are the small classes in `app/src/main/java/dev/tinyclient/app` (permissions, audio
session and its foreground service, Camera2, MediaProjection, MediaCodec, the sign-in WebView, the
Custom Tab), driven from Rust by JNI; `docs/mobile-platform.md` ("Android, as built") lists them.

## What is here

| File | Why |
|---|---|
| `settings.gradle.kts` | plugin/dependency repositories, `:app` module |
| `build.gradle.kts` | AGP **9.5.0**, Kotlin **2.4.21** (declared, not applied — no Kotlin source yet) |
| `app/build.gradle.kts` | `compileSdk`/`targetSdk` **36**, `minSdk` **29**, NDK **30.0.16248370**, `jniLibs` packaging, 16 KB notes |
| `app/src/main/AndroidManifest.xml` | `NativeActivity`, `android.app.lib_name = tinyclient`, `hasCode="false"` |
| `gradle/wrapper/gradle-wrapper.properties` | Gradle **9.6** (the wrapper script/jar is not committed; see below) |

`app/src/main/jniLibs/` is generated by `scripts/mobile/build-android.ps1` (Windows) or
`scripts/mobile/build-android.sh` (Linux/macOS) and is gitignored.

## Versions, and why

* **AGP 9.5.0** — current in October 2026; requires Gradle 9.6. AGP 9 removed `applicationVariants`
  / `libraryVariants`, so the UniFFI docs' Gradle snippet does not work as written. This project
  never uses them: the `.so` files are prebuilt by `cargo ndk`.
* **NDK r30 LTS (`30.0.16248370`)** — compiles 16 KB-aligned by default. cargo-ndk 4.1.2 adds
  `-Wl,-z,max-page-size=16384` only for NDK <= 27.
* **minSdk 29** — Android 10. Scoped storage and the `execve` restriction that rules out a
  spawned `chatd`.
* **targetSdk 36** — mandatory for new apps and updates since 2026-08-31.
* **16 KB pages** — Play blocks updates without 16 KB support from **2027-02-01**. Both halves are
  configured (`useLegacyPackaging = false`, NDK r30), but neither is verified on this machine.

## First build

```powershell
# from the repository root, Windows
rustup target add aarch64-linux-android x86_64-linux-android
cargo install cargo-ndk --version 4.1.2 --locked
$env:ANDROID_NDK_HOME = "$env:LOCALAPPDATA\Android\Sdk\ndk\30.0.16248370"
.\scripts\mobile\build-android.ps1
```

```bash
# Linux/macOS
rustup target add aarch64-linux-android x86_64-linux-android
cargo install cargo-ndk --version 4.1.2 --locked
export ANDROID_NDK_HOME="$HOME/Android/Sdk/ndk/30.0.16248370"
scripts/mobile/build-android.sh
```

The APK lands at `mobile/android/app/build/outputs/apk/debug/app-debug.apk`.

## One-time Gradle bootstrap

No `gradlew` is committed, because the wrapper jar is a binary this checkout could not generate.
Create it once (or install Gradle 9.6+ and call `gradle` directly — the build scripts accept both):

```bash
cd mobile/android
gradle wrapper --gradle-version 9.6.0
```

Then `./gradlew :app:assembleDebug` works. CI uses `gradle/actions/setup-gradle@v5` and does not
need the wrapper.

## Verifying 16 KB support (needs the NDK + an emulator)

```bash
llvm-readelf -lW mobile/android/app/src/main/jniLibs/arm64-v8a/libtinyclient.so | grep LOAD
# every Align must be 0x4000
$ANDROID_HOME/build-tools/36.0.0/zipalign -v -c -P 16 4 app-debug.apk
adb shell getconf PAGE_SIZE   # 16384 on a 16 KB image
```

None of this has been run here: no NDK, no SDK, no device on this machine.
