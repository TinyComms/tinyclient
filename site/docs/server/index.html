Tiny server

A self-hosted server for one community, with tinyclient as its app: text channels, direct messages, voice rooms and one picture.

tinyserver is open source under the MIT license and written in Rust. One deployment is one community. Its owner runs it; the tinyclient project does not host it, does not take its credentials, and does not carry its messages. See it in pictures, or read the source on GitHub.

The project is early, and it has had no independent security review. Each page here says what is not built and what is not tested.

What a server does

AreaWhat works today
TextText channels in categories and direct conversations between two members: replies, files, reactions, edit, delete, typing and read state
VoiceVoice rooms people drop into, and calls between two members. Mute, deafen and who is speaking.
VideoOne picture per listener: a screen share, or one other person’s camera
EncryptionCalls end to end when every app in the call can. Text and files end to end in conversations created encrypted.
Sign-inNo passwords. Passkeys the server checks itself, an OpenID Connect provider, or both.
PeopleOwners, roles with permissions, overrides per room and channel, invites with uses and an expiry
ModerationServer mute and deafen, move, disconnect, timeout, kick, ban and an audit log
FilesUploads scanned before anyone can fetch them; images re-encoded; risky types refused
BotsApplication bots that can read and manage rooms and read the member list

How it fits together

  • tinyclient is the app. A member adds the server beside their other networks; tinyclient talks to it directly from their computer.
  • tinyserver is one program: an HTTP API, a live socket for events and call setup, the sign-in pages, and the call server.
  • Postgres holds accounts, messages and settings. Files live on a volume. ClamAV scans uploads.
  • Web traffic reaches the server through a Cloudflare tunnel, or a reverse proxy of your own. Call audio and video go straight to one port on the host.
  • tinyclient.io takes no part. Its invite page only opens the app, and the invite’s secret never reaches it.

What it is not

  • Not federated. A server is one community, and two servers do not talk to each other.
  • Not hosted by the project. Someone runs each server and can read what is not end-to-end encrypted.
  • Not usable from a browser. tinyclient is the app; the only pages a server shows are for signing in.
  • Not able to carry calls from a host that cannot open a port. A relay is not built yet.
