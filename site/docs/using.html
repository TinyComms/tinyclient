Using tinyclient

One window for every network you sign in to. What each network can do is on Networks & terms.

The window

You start tinyclient. It starts chatd when nothing is already listening on the local socket. chatd holds the connections and the cache. The window only draws what chatd reports.

  • The inbox is one list across Slack, Discord, Telegram, Teams, Signal and Messages.
  • A network’s own sidebar is there too: servers, workspaces, folders, teams. A Tiny server you add has its own place on the rail, laid out as a Discord server is.
  • Quick Switcher finds a conversation, a person or a server in the local cache. Its Search messages row, and Edit › Find, open the search pane: this conversation, this space, or everywhere. Each keystroke searches the cache, and a hit opens its conversation on that message. Enter asks Discord’s own search for a Discord server or channel; other networks are not searched yet. tinyclient --text --search searches the cache from a terminal.
  • Your newest message shows whether it is sending, sent, delivered or read, where the network says so. Discord and Slack have no read receipts, so they show one tick.
  • A conversation is marked read only when the window is active, that conversation is open, and the message is on screen.
  • What is not built yet opens in the official app, on that item. The list is on Networks.
  • On Windows the window draws its own minimize, maximize and close buttons, with Snap layouts. On Linux it draws them where the desktop does not, as on GNOME with Wayland.

tinyclient --text prints account status and the inbox as lines of text, then exits. An interactive terminal is not built. The socket protocol is the API for one.

Notifications

chatd decides what notifies, so notifications arrive with the window closed. By default a direct message or a mention notifies, one notification per conversation with its newest lines, taken away once you read it, here or on another device. Your own messages, history and the conversation open in front of you never notify. Conversations you muted never notify, and Do Not Disturb set in Slack or Discord is followed here. Calls ring with Accept and Decline.

  • Settings › Notifications: on or off; direct messages, groups, mentions and Tiny server activity each on their own; how much a notification shows, and a separate choice while the screen is locked; pause, and quiet hours; whether calls still ring; the badge and the taskbar flash; and Send a test notification.
  • Settings › Sounds: Pebble, Drop, Tap, Chime or Glass for messages and mentions, Soft ring or Classic ring for calls. tinyclient plays them itself, so notifications are posted silent. A conversation’s Details has its own Sound row.
  • The Dock icon on macOS, or the taskbar button on Windows, shows how many things want your attention, and the taskbar button flashes for something new while the window is in the background.
  • Windows notifications have Reply and Mark as read. macOS needs the app bundle. Windows is where notifications have been tried most; reports from macOS and Linux are welcome.

Calls and voice

Calls run on Discord, in DMs and voice channels, and on a Tiny server you add. Settings › Voice and Audio & video apply to both.

  • Microphone: voice activation with a sensitivity you can see, or push to talk, with a priority key for priority speakers. Echo cancellation, noise suppression and automatic gain are on by default.
  • Keys: push to talk, mute and deafen can work while tinyclient is in the background: keys and mouse buttons on Windows; keys on macOS once you allow Input Monitoring; keys and the middle button on X11. On Wayland, mute and deafen work only while the window is in front.
  • Devices: the microphone and speaker you pick are kept by their system id. If one goes away, the call uses another and says so, then switches back when it returns. Virtual devices are labelled and never picked for you. Play test sound and a level meter check them.
  • In a call: the signal bars open Call health, with ping, jitter, loss and plain-language hints. tinyclient says “You’re muted” when it hears you while muted, and rejoins by itself after a lost connection.

Updates

While the window is open it asks GitHub, about once an hour and again shortly after launch, whether a newer release exists. The request is User-Agent: tinyclient/<version> and nothing else: no account, no machine id.

A newer release is shown until you dismiss it. Check for Updates… asks again. With automatic install on, and only for an installed copy (not a build under target/ or a copy in the Nix store), the archive is downloaded, checked against that release’s SHA256SUMS, and on macOS checked with codesign before it is kept. It replaces this copy when you quit. The menu then says Restart to Update. A failure is remembered for a day and said only in About.

When the newest release has the same version number as this copy, tinyclient asks GitHub whether this build’s commit is older than the release, and offers the release if it is. About shows the version and the commit. On Windows, the update waits for tinyclient’s programs to stop, rolls back if a step fails, and opens the app again either way. A copy you cannot write to offers the download instead.

Linux: leave chatd running

By default, quitting the window stops the daemon it started. Logs go to chatd.log.

The .deb, .rpm, Arch and Nix packages can install tinyclient-chatd.service. The unit is disabled. With it disabled, nothing about startup changes.

To let systemd manage the daemon, quit tinyclient first so its daemon releases the socket. From a terminal in your graphical session:

systemctl --user daemon-reload
systemctl --user import-environment WAYLAND_DISPLAY DISPLAY XDG_CURRENT_DESKTOP
systemctl --user enable --now tinyclient-chatd.service
journalctl --user -u tinyclient-chatd.service -f
  • Import only the variables your session sets. Wayland sets WAYLAND_DISPLAY; X11 sets DISPLAY. If you use XDG_DATA_HOME, import that too, so the window and the daemon share a data directory.
  • The Secret Service has to be running and unlocked on the same user session bus.
  • With the unit enabled, opening tinyclient asks systemd to start the daemon if needed. Quitting the window leaves the daemon receiving. The window’s “Keep receiving” preference does not override an enabled service.
  • After an upgrade: systemctl --user restart tinyclient-chatd.service.
  • To stop background activity, quit the window and run systemctl --user stop tinyclient-chatd.service.
  • The unit follows graphical-session.target. With a standalone compositor such as dwl, import the display environment after the compositor starts, then start the service, and stop it when you leave the session. Do not enable lingering for this service: sign-in windows need a live graphical session.

To go back to automatic startup, quit the window and run systemctl --user disable --now tinyclient-chatd.service.

For sign-in diagnostics, import TINYCLIENT_LOGIN_DEBUG=1 into the user manager, restart the service, and watch the journal. Unset it when you are done. The messages name whether the helper is waiting on a login page. They do not include credentials.

A scratch directory (TINYCLIENT_DIR) and an explicit TINYCLIENT_CHATD always start the daemon directly. For a source build or a .tar.gz install, copy packaging/linux/tinyclient-chatd.service to ~/.config/systemd/user/, set ExecStart to the absolute path of that chatd, and reload the user manager. Keep the four programs together. AppImage builds stay on automatic startup.
