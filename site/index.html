tinyclient

One native app for Slack, Discord, Telegram, Microsoft Teams and Signal. It runs on your computer and talks to each network directly. There is no tinyclient server, and nothing is sent anywhere else.

Download the latest release View source

macOS 13+ on Apple silicon · Linux x86_64 · Windows x86_64 · Free and open source, MIT · Install guide

Early software. Discord and Slack have been used on real accounts. Teams, Telegram, Signal and voice calls have so far run only against local fakes of each network. tinyclient is unofficial, and using it can break a network’s terms: read the terms for each network before you sign in.

Principles

Built so you can check it

Every claim below points at the code or document that makes it true.

No server in the middle

There is no tinyclient service and no account with us. A process on your computer, chatd, connects to each network you sign in to. Files are fetched only from an allow-list of each network’s own hosts, and a link in a message is never fetched.

See blobs/fetch.rs

No telemetry

No analytics, usage pings, update check or crash upload. A crash is written to crash.log on your disk with tokens and cookies redacted. “Copy report” puts it on your clipboard; sending it is up to you.

See protocol/src/crash.rs

Local first

Messages are cached in SQLite on your disk. Sessions live in the system credential store: the macOS keychain, Windows Credential Manager or the Secret Service on Linux. Signing out deletes the session, the cached messages and the media.

See Privacy & security

Native, with budgets

The window is drawn with GPUI, the GPU UI framework from the Zed editor. No Electron and no embedded web client. Every feature has a memory, speed and idle-CPU budget, measured from outside the process.

See 07-budgets-and-risk.md

Calls cost nothing until you make one

Voice runs in its own process, mediad, which starts when a call connects and exits when it ends. No audio code is loaded the rest of the time, and the sign-in window is a separate process that exits when you are in.

See Architecture

Never acts for you

No reaction, edit, friend request, read receipt or status change goes out unless you made it. A conversation is marked read only when the window is active, it is open and the message is on screen.

See docs/architecture.md

Privacy and security

What it keeps, and what it never does

Kept on your computer

  • Sessions in the system credential store, one item per network under the service tinyclient. Never in the database or a log.
  • Messages in chat.sqlite: the newest 2,000 per conversation, nothing older than 90 days unless you opened it in that time.
  • Media you have looked at, in media/, capped at 500 MB and evicted oldest first.
  • Signal’s keys in signal/, each value sealed with a key that only the credential store holds.

Never

  • Sends anything to the people who make tinyclient. There is nowhere to send it.
  • Runs an embedded copy of a network’s web app. The one web page it shows is the sign-in page, in its own process.
  • Writes a credential to a log. Tokens, cookies and keys are redacted before anything is written.
  • Automates anything: no scheduled actions, no bulk reads, no friend requests or joins you did not make.

Known limits, stated plainly

  • The message cache is not encrypted by tinyclient. Use your system’s disk encryption.
  • The local socket is not authenticated: any program running as your user can connect to it, as it can read your files.
  • Signal safety numbers are not shown yet, and a contact’s new identity key is trusted automatically.

Help make it real

tinyclient is MIT-licensed and developed in the open. The most useful help right now is not always code.

Use it on a real account

Teams, Telegram and Signal have only met fakes so far, and Linux and Windows have had little use. A bug report with the redacted log is as valuable as a patch.

Try it with no account

A demo mode fills a scratch directory with invented servers and people and never touches your keychain.

Run the demo → 
git clone https://github.com/itz4blitz/tinyclient
cd tinyclient
cargo test --workspace
TINYCLIENT_DIR=/tmp/tinyclient-demo cargo run -p chatd -- --seed-demo
TINYCLIENT_DIR=/tmp/tinyclient-demo cargo run -p tinyclient --features gui
